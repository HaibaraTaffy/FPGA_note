## 校验原理
---
例如         A     B 两个信息
码字一 :   00    01(CD占据其他两个合法编码)
码字二 :   00    11(其他编码是非法的)

码距 : 两个合法码字 对应位上数字的不同 位的个数
码字一 A B的码距是1 码字二 A B的码距是2

在传输过程中 可能会导致传输的信息变化
以码字一为例 如果传的是A 在传输过程中跳变 则可能接收端接收到不一样的信息

**码距为一**的坏处就是无法判断是否受到干扰 因为所有的编码都是有含义的
若是码字二 则一个跳变 可以知道出错了 但是不知道错在哪
**码距大于一**之后 就可以有了纠错的功能 未使用的编码 在出错的时候 可以指示出错误

## 奇校验 偶校验
---
>奇校验

保证一段数据中出现奇数个1
一整段数据 = 校验位 + 信息位

例如         A     B 两个信息
码字一 :   1_00    0_01(CD占据其他两个合法编码)
码字二 :   00    11(其他编码是非法的)

这样 码字一的码距提升了 具有了检测的功能
发送端发送一整个数据 接收端事先约定好奇校验  具有一定的检测

**限制** : 只能检测出 在一次传输中 发生奇数个错误 的情况
**原理** : 增加了码距
**特点** 仅需要添加一位即可

>偶校验

规则和逻辑上与奇校验一样 形式上 一段数据中偶数个1
奇校验的校验位取反 -> 偶校验

> 放置规则

一般来说 奇偶校验码 放在有效信息位前面 二者拼接组成了 奇偶校验码

# 海明码 了解
---
奇偶校验码不能纠错的原因 : 一整串数据 共同产生校验位 只能看到整体 不能看到局部

海明码设计思路 : 分组校验 -> 设计多个校验位 -> 校验位标注出错的位置
最经典的能力就是 : **单比特错误纠正**

![[Pasted image 20260909220113.png]]

关键公式 `2^k >= n + k + 1`

海明码求解步骤 直接举例
![[Pasted image 20260909220555.png]]

更正一下 **校验位P_i 放在海明码号为 2^(i-1)的位置上 信息位按顺序放置**

为什么这么放?因为这样子 每个校验位的位置 分别对应二进制
```
1 = 001
2 = 010
4 = 100
```
这三个校验位刚好可以组成一个 **3 bit 的错误位置编号**。
而这3bit可以表示 0-7
即
- 0：没有错误
- 1~7：第几位出错

![[Pasted image 20260909223627.png]]

选出信息位对应的海明码位 转换成二进制
对二进制数进行分析 如图 选取同一位置的值 值为1的对应的信息位参与运算 进行异或 得到一个校验位
按顺序运算 得到所有校验位

例如 P1 可以看到 3 5 7的二进制数的最低位都是1 所以参与运算 得到P1

**信息位确定后 校验位的值也确定了**

![[Pasted image 20260910193640.png]]
接收端需要对接受到的进行异或 即进行偶校验

最高明的地方在于 **哪些校验出错 本身就组成了"错误位置的二进制编号"**


## 循环冗余校验码 CRC码
---
**核心** : 把二进制数据当成多项式 做模2除法 用余数作为校验码 通常用来**检错 而不是纠错**

CRC 的做法是：
```
原始数据
   ↓
CRC计算
   ↓
原始数据 + CRC余数
   ↓
发送
```
接收端收到之后 再进行一次相同规则的 CRC 检查 
- 余数符合预期 -> 通过
- 否则报CRC Error -> 检测到传输错误

> 把二进制看成多项式

例如数据 1101 CRC把每一个bit当成多项式系数 即
`1 * x^3 + 1 * x^2 + 0 * x + 1 * x^0`
即`x^3 + x^2 + 1`

> Generator Polynomial 生成多项式

还是以上面为例 选择 `G(x) = x^3 + x^2 + 1`
那么 `G = 1011`

> CRC校验位有多少位

生成多项式的**最高次数** 就是CRC的位数
以上面为例 G(X)最高次数是3 G本身4位 但是CRC位是**3**位

> 发送端第一步 : 原始数据后补0

还是上面为例 原始数据 1101 生成多项式 1101
于是原始数据后 补3个0 为3个CRC位留出位置
`1101000`

>第二步 做除法

`1101000 / 1011`
做模二除法 加法和减法都等价于 异或
所以CRC的长除法 **本质上就是不断进行异或**

实战 : 
先看前4位 `1101(000) 1011 -> 0110(000)` 按位异或
把下一位0拉下来 于是`1100(00) 1011 -> 0111(00)`
继续`1110(0) 1011 -> 0101(0)` 
最后一个 `1010 1011 -> 0001`
最后取3bit余数 于是 **CRC = 001**

>第三步 发送

原始数据 + CRC = 1101+001 =1101001
原来的三个0要被余数替换

>接收端检查

接收端收到 1101001 进行同样的模2除法 如果不出错 则余数应该为 000
可以尝试
`1101 1011 -> 0110`
`1100 1011 -> 0111`
`1110 1011 -> 0101`
(下一步应该拉1)
`1011 1011 -> 0000`
没毛病

一旦出错 马上可以检验出来 但是不知道哪里错了

>关联FPGA

在FPGA中 可以使用移位寄存器 + XOR进行CRC校验
一般也可以直接用CRC校验生成器生成代码

会用到`LFSR Linear Feedback Shift Register 线性反馈移位寄存器`
因为是一位一位进行计算的 很适合FPGA的流水式计算
