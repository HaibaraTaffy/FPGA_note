
**PCIe 是连接 CPU 系统和 FPGA 的高速互连协议**
**MMIO 让 CPU 可以把 FPGA 的一部分寄存器空间映射进自己的地址空间**
**PIO 是 CPU 亲自通过这些 MMIO 地址访问 FPGA**
**DMA 则是 FPGA 或 DMA Controller 主动通过 PCIe 大批量访问主机内存**

## PCIe 的角色
---
架构图
```
          Host PC

        ┌─────────┐
        │   CPU   │
        └────┬────┘
             │
             │ CPU内部总线
             ▼
      ┌──────────────┐
      │ Root Complex │
      └──────┬───────┘
             │
============= PCIe =============
             │
      ┌──────▼───────┐
      │ FPGA PCIe EP │
      └──────────────┘
```

- RC(Root Complex 根复合体) : CPU/内存系统进入PCIe世界的入口 负责链接CPU和各个 PCIe EP
- EP (Endpoint 端点设备) : FPGA的 PCIe核通常就是一个 Endpoint 或者理解为 终端

在PCIe DMA PIO 的关系中 `PCIe` 是高速公路 而`PIO DMA` 是不同的运输方式

## PCIe Enumeration BAR MMIO
---
在 CPU/PC启动时 操作系统会进行
**PCIe Enumeration 枚举**
获取PCIe总线上的信息 例如 `有哪些设备 每个设备是谁 需要多少地址空间 有什么能力`

在这个时候 FPGA的 PCIe Endpoint Hardcore 会暴露自己的配置空间 其中就有BAR
**BAR Base Address Register 基址寄存器**
作用是 `FPGA高速系统 希望给我分配一段地址空间`
即创建**MMIO映射**

例如
假设 FPGA 内部设计了几个寄存器
```
BAR0 + 0x00 CTRL
BAR0 + 0x04 STATUS
BAR0 + 0x08 MODE
BAR0 + 0x0C LENGTH
```
CPU 看到的地址可能是：
```
0xA000_0000 CTRL
0xA000_0004 STATUS
0xA000_0008 MODE
```
于是 CPU 执行：
```Store 0xA000_0008```
系统发现
```这个地址属于 PCIe FPGA```
于是不会访问 DDR 而会走：
```
CPU
↓
Root Complex
↓
PCIe
↓
FPGA
↓
BAR Decoder
↓
MODE Register
```
**BAR 就是 FPGA暴露出来的 MMIO窗口**

## PCIe中的 PIO
---
上面的路径 就是一个 PIO 的路径
也可以理解成
```
CPU
↓
Load / Store
↓
MMIO Address
↓
PCIe BAR
↓
FPGA Register
```

这个时候 RC会充当 `Address Decoder` 负责发现地址属于 PCIe地址 把这个访问转换成 `TLP`

内部会包含
```
Address
Data
Length
其他控制信息
```
然后在PCIe总线上传输
构成下图的数据流 :
```
CPU
↓
Root Complex
↓
PCIe TLP
↓
FPGA Endpoint
↓
BAR0 + 0x10
```

无论是从PCIE读还是写 均是通过这一条路线
但是由于PIO的局限性 只适合配置参数 读取状态等小数据事务

## DMA的角色
---
在大量数据传输时 可以通过在FPGA 里搭建
```DMA Engine```
它可以主动通过 PCIe 发起访问
这时候路径变成：
```
FPGA DMA Engine
↓
PCIe Endpoint
↓
PCIe
↓
Root Complex
↓
Host Memory
```
此时 **在使用DMA时 FPGA不再只是被CPU访问 FPGA也可以主动访问主机内存 此时FPGA成为 Bus Master**
PCIe DMA的基础就在于此 PCIe是一个**双向的事务系统**

假设 PC 内存中准备了一块 Buffer
```Host Buffer```
**驱动**获得一个 DMA 可用地址
然后 CPU 先通过 PIO 告诉 FPGA：
```
DMA_DST_ADDR = Host Buffer Address
DMA_LENGTH = 4096
DMA_START = 1
```
以上属于PIO的控制部分
然后 FPGA DMA Engine 开始：
```
FPGA Data
↓
DMA Engine
↓
PCIe Memory Write
↓
Host RAM
```
这就是DMA的作用

## 完整例子
---
假设你 FPGA 采集摄像头图像 然后传给 PC
第一阶段：
```
PC软件
↓
分配Buffer
```
第二阶段：
CPU 通过 PCIe BAR：
```
写目标地址
写长度
写START
```
这一步：
```
PIO
+
MMIO
```
第三阶段：
FPGA：
```
Camera
↓
Image Pipeline
↓
FIFO
↓
DMA Engine
```
第四阶段：
DMA Engine：
```
PCIe Memory Write
↓
Root Complex
↓
Host DDR
```
第五阶段：
传输完成 FPGA 可以发：
**MSI Message Signaled Interrupt 消息信号中断**
通知 CPU
```DMA Done```
所以整个过程：
```
                 CPU
                  │
             PIO + MMIO
                  │
                  ▼
             PCIe BAR
                  │
                  ▼
                FPGA
                  │
              DMA Engine
                  │
               PCIe
                  │
                  ▼
             Host Memory
```
